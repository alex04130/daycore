# Daycore 前端设计简报（致 Claude Design）

> 任务：并行产出 **3 个范式级不同的前端方案**，供逐一比较。方案一已在体验推敲中定稿，请深化执行；方案二、三给出范式骨架，视觉语言与细节全部开放。三案消费同一套 API v2.3，可并存部署、随时切换——前端无版本只有名字，请给每案起名（下文名字是工作代号，可推翻）。

## 〇、区分度要求（先读这条）

**差异必须在架构层，不许只在风格层。** 判据：把三案的界面截图去掉颜色和文字，仅凭布局与交互骨架就能认出是谁。每案的"主表面是什么、导航怎么走、提案在哪出现、收集从哪进"必须互不相同。禁止把方案二、三做成方案一的换肤——那种"随便让 AI 改改就能得到的差异"不算数。

## 一、硬约束（三案共同遵守，全部出自《体验内核》）

1. 五铁律 + 反羞耻底色：不变红、不积债、无 streak、无完成率大字报。
2. 注意力阶梯预算：L2 卡 ≤3 张进堆叠（或等价的单一停车场）、推送 ≤3 条/天、L0 只是安静小数字。
3. 响应多态三型必须可渲染：做了 → 轻卡 + 撤销；查到 → 浮层 + 视图变化；要确认 → 提案。只有 Companion 语境是对话流、有聊天史。
4. 提案渲染义务：接受 / 拒绝 / 追问三动作恒定可达；含时段的提案**能用虚影就用虚影**（实线/虚线/虚影三线语义）；过期自动消失不留尸体。
5. 表达入口无处不在：任意界面一步内可对 agent 说话/上传；收集一条杂念 ≤2 秒。
6. 任何 AI 动作 3 秒内可撤：撤销路径不超过两步。
7. 石化语义：过去块换装"记录"态，只接受对账与注释；拖回未来转译为重新安排。石化线 = min(now−5h, 今天 00:00)。
8. 无欢迎页、无强制导入：冷启动第一屏就是可用的空状态 + 诚实引导。
9. 不做月视图：远期一览 = Deadline 雷达（列表语义）。
10. Cmd+K 不做（浏览器占用）。

## 二、方案一「长卷」——时间画布（已定稿，深化执行）

**范式一句话**：时间是一块连续的空间画布，用户在地图上看自己的日子。

- **主表面**：垂直时间画布。日视图捏合成周（到周为止），横滑翻日，拖块到边缘自动滚动跨日。
- **导航**：5 席书签——`资料｜足迹｜今天｜展望｜伙伴`，今天居正中放大，是永远的迷路回家键。中间三席是同一块画布的三个镜头位，点击 = 镜头移动。锚位原则：默认页要么最边、要么正中且放大。
- **输入**：底部恒定输入框，永不移动失焦；无 URL 路由，页面切换是内容区动画。
- **形态方言**：手机 = 流体 Dock；桌面/平板 = 四缘抽屉（平板不做中间态，两极分化）。
- **提案渲染**：含时段 → 时间轴虚影 + 确认卡；不含时段 → 堆叠卡。堆叠底部物理露出下一张的极小边缘，上滑拉取。
- **空间引力**（本案专属方言）：拖起对象时四个引力井以呼吸微光示意——已有块（附着为材料）、某天空白（交给那天）、待泊区（改天再说）、资料书签（静默归档）。落点只是预填 intent 的 focus。
- **事件视界**：石化块换装记录质感，向远处滑就是足迹的河。
- **组件**：Mood 胶囊挂在今天页（打卡 + AI 一句话映出）；Settings 进头像菜单；晨导语卡上滑即走、过午消散。
- **停车场样式**（本案待设计细节）：Dock 动效参数、引力井微光形态、堆叠露边拉手样式、导语卡与周信版式文体。

## 三、方案二「此刻」——单件流（新案，骨架如下）

**范式一句话**：画面永远只回答一个问题——现在做什么。为"连日历都不想看"的人做的最彻底省心形态。

- **主表面**：全屏一张当前块卡（或空档卡），下一件事在底部露头。没有网格、没有轴——概览被刻意折叠。
- **推进**：上滑 = 完成/送走；长按或菜单 = 没做/换一个/推迟（推迟走提案转译）。块与块之间的过渡帧顺手心情打卡（一次滑动完成，可跳过）。
- **概览到达**：下拉展开今天的迷你缩略轴（peek，只读为主）；继续拉到底进足迹/展望。**概览是抽屉，不是家。**
- **提案渲染**：天然契合待发池的"投递时刻"语义——开屏、块结束的间隙整屏出现一张提案（"接下来 1 小时空着，看《悉达多》？"），一滑接受、一滑推开。健康日 ≤3 张不变。
- **收集**：常驻一枚极小胶囊（或长按任意处唤出输入），说完即走 L0；此案语音优先级最高。
- **撤销**：每次滑动后顶部留 3 秒撤销条；账本从菜单一步可达。
- **适配**：手机为主场，天然延伸到手表和嵌入式小屏（同一范式缩到一行字 + 两个键）。桌面形态自行提案（悬浮小窗？）。
- **已知风险与兜底**：失控感（看不到全天）→ 下拉 peek + 晨导语给全貌；空档焦虑 → 空档卡本身是正当状态，文案反羞耻。
- **开放度**：视觉、动效、桌面形态全开放；但"单件全屏 + 概览折叠"的范式不许滑回长卷。

## 四、方案三「顺流」——叙事流（新案，骨架如下）

**范式一句话**：一天是一篇由你和 Daemon 共同书写的日志，主表面是一条自上而下的时间叙事流。

- **主表面**：单条垂直流，统一卡语法承载一切条目：晨导语、块的开始/完成行、L0 静默行（折叠成小字组）、提案插页、心情、随手记。now-line 是流中的一道横线；向下滚是未来的"预告"段落（明天自然出现在流的下方），向上滚是过去。
- **重要边界**：这条流**不是聊天史**——它是账本的渲染。每个条目 = 账本行/块/提案，可撤销可跳转；agent 的话不进流，只有事实进流（共识 4 不破）。
- **导航**：滚动即时间旅行，书签退化为一个"回到现在"按钮；资料与展望雷达是侧入口（形态自定）。足迹与今天在此案里是同一条流的不同滚动位置——这是它和长卷最深的结构差异。
- **石化表达**：条目随滚动石化线自然转为记录质感（变灰/图钉/左缘变化，自定），对账动作就地完成。
- **提案渲染**：流中插页卡，位置就是它指向的时段；过期从流中枯萎（缩成一行小字或消失）。
- **输入**：底部输入框，说的话"写进流里"——写入的是结果条目（"✓ 已记录……"），不是对话气泡。
- **修改**：拖拽退位，改期以条目菜单 + 一句话指令为主。
- **适配**：手机与桌面同构（桌面可加宽为双栏：流 + 常驻上下文栏，自定）。
- **已知风险与兜底**：信息密度失控 → L0 强制折叠成小字组、每屏条目设上限；"像聊天软件"的误读 → 卡语法必须明显区别于气泡。
- **开放度**：视觉全开放；"单流 = 账本渲染 = 过去现在未来连续滚动"的范式不许退化成普通列表页。

## 五、每案交付物

1. 概念一页：范式一句话 + 目标用户姿态 + 与另两案的差异声明（各一句）。
2. IA 图：主表面、全部可达区域、层级关系。
3. 五幕关键界面：冷启动第一屏（空状态）、健康日、危机日（L2 卡 + 一条推送）、收集一条杂念的全路径、撤销一个 AI 动作的全路径。
4. 提案渲染表：L0/L1/L2/L3 + 虚影态在本案中各自长什么样。
5. 石化与足迹的表达。
6. 平台适配：至少手机 + 桌面各一幕。
7. 命名 + 一段设计语言陈述。

---

## 六、评审维度（我会这样比）

1. 收集一条杂念的秒数与步数。
2. 撤销任一 AI 动作的路径长度。
3. 健康日模拟的打扰感（一天下来被叫住几次）。
4. 迷路后回家的成本。
5. 反羞耻观感：没完成的一天在此案里长什么样。
6. 冷启动第一屏的诚实度与吸引力。
7. 区分度测试：去色去字认得出谁是谁；每案范式能否一句话说清。
