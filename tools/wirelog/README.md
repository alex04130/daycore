# wirelog — 看清我们到底往模型发了什么

一个记录型反向代理。`models.yaml` 里每个模型都有自己的 `base_url`，把它指向这个代理，就能拿到**两侧的明文** —— 不需要 MITM 证书，也不用改 hosts。TLS 让 tcpdump 在这件事上没用，因为要看的字节都在加密流里面。

```bash
go run ./tools/wirelog -listen 127.0.0.1:8899 -upstream https://api.deepseek.com -out /tmp/wire
```

然后把待测模型的 `base_url` 改成 `http://127.0.0.1:8899`（或 `.../v1`，看上游），跑一次真实请求，去 `/tmp/wire/` 读。

## 两个设计决定

**响应是边转发边落盘，不是先缓存再落盘。** SSE 必须持续流向客户端，缓存它会把「流式」这条正在被测的路径变成非流式的，于是测的就不是那条路了。每写一块就 `Flush`。

**一次交换一个文件。** 最初写同一个文件，结果一跑就坏：当时有个浏览器也打到了代理上，23 个并发请求的片段互相穿插，日志直接不可解析。单把锁只能保证单次写不撕裂，保证不了一次交换的完整性。

## 它会漏掉什么

- `Authorization` 与 `X-Api-Key` 在日志里被替换成 `<redacted>`，其余请求头原样记录。
- 代理**不做认证**。它监听 127.0.0.1，转发客户端自己带的凭证 —— 也就是说本机上任何进程都能借它打上游。开发机上可以接受，用完就停掉。
- 请求上的 `Accept-Encoding` 会被删掉，好让记下来的响应体可读。所以你看到的不是线上那次压缩后的字节。
