# Daycore 体验内核（端无关）

> 由《体验沙盘 v2.3》第六轮拆分而来。本文档只写**所有端共同遵守的语义**：数据怎么动、agent 怎么想、时间怎么算。任何界面形态、布局、动效一概不在此文——那些在姊妹篇《前端设计简报》里。不是宪法，不冻结。API 契约名 v2.3。2026-08-13 补结构核对。

---

## 一、定位与多端原则

替不擅长规划的人省心的 AI 日程管家：Daemon 持续产出默认正确的计划，用户只做两件事——丢东西进来、对提案点头或摇头。

**多端架构**：API v2.3 是唯一契约。有界面的消费者叫**前端**（无版本只有名字：琉璃、纸屿、汀……）；无界面的叫**集成端**（嵌入式、智能家居、服务器对接、QQ 通道）。同一平台可并存多个前端，用户可换、可选、可自写。后端可烧：烧 HTTP 表面；工具集、提示词分层、cron、存储、OperationLog 留下。

### 1.1 语言：用户自选一主一副，每端首页都有开关（2026-07-26 追加）

**每个前端的首页都必须有语言切换，且必须长成那一端自己的样子。** 四端是范式级不同的四套设计，一个统一样式的语言按钮插到哪一端都是补丁 —— 琉璃的玻璃质感、纸屿的纸面、汀的克制留白，各自怎么做由那一端决定，这里只规定它必须在、必须在首页够得着。

**一主一副是用户自己选的，不是部署定死的。** 部署只给**默认值**（`DEFAULT_PRIMARY_LOCALE` / `DEFAULT_SECONDARY_LOCALE`），给还没选过的人一个起点；选哪两种是用户在设置页的事，`i18n.Available()` 里的任何一种都能选。

为什么是两种而不是全部：控件得是一个按钮不是一个菜单。装了六种翻译的实例，不该让每个人的标题栏里多出一个六项下拉。为什么不是一种：第二种才是这个开关的意义 —— 读中文但想看某个词的英文说法，或者双语的人读一种、想一种。

**三层状态，别混**：

| 层 | 存哪 | 是什么 |
|---|---|---|
| 装了哪些语言 | `i18n.Available()`（内嵌 ∪ 文件 ∪ DB） | 这个安装能渲染什么 |
| 我的一主一副 | `SessionPrefs.primaryLocale` / `secondaryLocale` | 我的开关在哪两种之间切 |
| 我现在读的是哪一种 | `sessions.language` 列 | 首页开关翻的就是它 |

第三层是**状态**不是偏好，所以留在原来的列上；前两层是偏好，进 `preferences` JSON —— **零 DDL**。

- **前端从 `GET /api/version` 的 `locales.available` 读可选语言，不许写死** —— 那不是编译期列表，丢一个 `<locale>.json` 进 `LOCALES_DIR` 就多一种。
- 用户自己那两种从 `GET /api/session/preferences` 读；`list` 只有一项（副语言为空）= **隐藏开关**，不是禁用。
- **读时钳制、写时拒绝**：换了配对之后 `sessions.language` 可能落在配对之外 —— 读（`Pair.Resolve`）静默落回主语言，设置页照常打得开；写（`PATCH /api/session` 的 `language`）返回 `400 unsupported_locale`，因为那一刻是用户在主动选。改配对时后端顺手把 `language` 拉回配对内，免得有人卡在一个开关够不到的语言上。

**语言包不焊在二进制里**（`i18n.Catalog`，三层）：

```
数据库覆盖    控制台改，多实例共享     ← 优先
本地文件      LOCALES_DIR/<locale>.json
内嵌          Go 字面量，只有 zh-CN / en-US   ← 兜底
```

内嵌那两种是**地板不是全集** —— 它们只需要覆盖「没有数据库也没有文件时仍能把页面画出来并说清为什么」。加一门语言是一个翻译文件，不是一次发版。形状照抄 `prompt_overrides`（文件作种子 + DB 覆盖 + 立即生效），那是这个仓库唯一把配置做对的地方。

⚠️ **解析按 locale 逐层问，不是按层逐 locale**：回退链里的每一个候选语言，都先问数据库、再问文件、最后问内嵌。反过来做（先挑「哪一层认识这个 key」再在那层里跑回退链）会让数据库里一条半成品的法语覆盖，盖住下面那条完整的英文。

### 1.2 前端握手与主题：token 空间归前端，家族取并集（2026-07-28）

**前端是开放的。** 不只是我们这四端 —— 别的开发者可以做更多前端、更多平台的前端。这不是一个「以后也许」，它决定了下面每一条的信任模型：**前端上报的东西是第三方数据，不是我们自己的代码。**

**实现契约在 [`docs/specs/frontend-manifest.md`](specs/frontend-manifest.md)** —— 握手载荷、`kind` 的三档与字符底线、主题读写端点、给第三方前端的三条硬要求。以下只留裁决与理由。

#### 一、存储形状本来就够，不需要换数据库

`custom_themes.variables` 已经是 JSON 列，四个引擎都存得下自由文档（先例 `day_plans.blocks`、`proposals.rows_json`）。MongoDB 做这件事更自然，也**推荐**用它，但**不能成为要求** —— 否则等于把「支持四个后端」悄悄降级成「推荐 Mongo」。要搬走的是校验规则，它现在写死在 Go 里。

#### 二、两层身份，token 空间取并集

`buildHash`（构建指纹，派生不可改）+ `familyId`（主题兼容组，build 声明、**运维可在控制台改**）。主题、按端偏好、`ThemeSwitch` 全部按 **family** 存 —— 那才是一套主题有意义的单位，琉璃可以有 web/app/嵌入式三个 build 共享一套。

**并集不是子集检查**：新 build 带来新 token 就扩一条，已存主题因此缺那一条 → 运维触发一次**补算**（每个缺 token 的主题一次 AI 调用，按它现有配色补上；要花钱所以是显式动作），补完变量完全一致的**合并**。build 用不到的 token 由**前端自己丢弃**，后端不裁剪。控制台显示**差异**而不是通过／不通过。

**默认主题不进补算**（2026-07-29）：build 自带的那几套主题，值是前端作者随 manifest 报上来的，取并集就完整了。所以 `补算次数 = 缺新 token 的用户生成主题数`，默认主题恒为 0 —— **一个 family 刚部署时合并零成本**，成本随用户攒主题单调增长且不会自己变小。控制台在归入 family 的入口旁报当下的价钱并说明它只会变贵，但**不催** —— 拖着不合并是正当选择（还没想清楚两端要不要共用主题），报价只是让「什么时候便宜」不用猜。

#### 三、握手集成进 version API

前端必须先握手、先自我介绍，否则后端分不清连上来的是哪个前端。既然版本协商已经在那儿，就放一起：`POST /api/version` 带自我介绍，响应带后端裁决（`assignedFamilyId` / `rulesAccepted` / `newTokens` / `pendingThemeBackfill`）。`GET /api/version` 保持原样给匿名与老客户端。

#### 四、两条安全边界

**前端是开放的** —— 第三方与多平台前端是一等场景，不是「以后也许」。所以前端上报的东西按**第三方数据**对待，不按「我们自己的代码」对待。

1. **`kind` 任一时刻是封闭集合，但那个集合是数据不是代码**（2026-07-29 修正）。`themeColorRe`（`handlers_themes.go:34`）的注释点明它守的是「通过变量值注入 CSS/HTML 不可能」，这条不能丢；但「加一种 kind 要发一次后端」是先前那版把保证挂错了地方 —— 保证真正的落点是**一道与 kind 无关的字符底线**（任何值都不含 `url(` `;` `{` `}` `<` `\` `/*` 换行）。有了它，kind 集合就能像三层语言目录那样存在 DB／文件／内嵌里，**加一种是插一行不是切一版**。三档：原语（六种，封闭）／组合子（`one-of[…]` `list-of<kind>` `nullable<kind>`，前端随便用，因为表达不出原语表达不了的东西）／前端自带 pattern（要运维批准，与 `theme.rules` 同一道门；负担得起是因为 **Go 的 regexp 是 RE2，线性时间无回溯，构造不出灾难性回溯**）。**纯字符串不行**：kind 主要是给 AI 的类型签名 —— 没有它，补算「给这 37 套主题补上 `--tab-bar-h`」这句话不成立。AI 生成的主题落地前逐 token 校验 key、kind、再过字符底线。
2. **`theme.rules` 未经运维批准不进 LLM**。前端可以主张一段、运维可以改并决定是否采用；没主张或没批准 → 后端按 token 清单机械生成，前端照样能用 AI 配主题，只是提示词是后端写的。**注入面默认为零**，批准是「我读过这段文字」的显式动作。

#### 五、每个前端必须有首次安装配置界面

`/setting` 或同等结构，至少能配「连哪个后端」。理由直接来自开放前端：把后端地址写死的前端只能对着一个部署用，而自部署是这个项目的常态。这个界面同时是语言开关（§1.1）与主题选择的落点。

#### 六、落地归属（批次 F7）

两张新表（`frontend_builds` / `frontend_families`）+ 两处加列（`custom_themes.family_id` / `theme_switch_log.family_id`）+ 按端当前主题进 `SessionPrefs`（零 DDL）+ 主题补算作业走 `job_runs`。⚠️ **与 F 的其它 DDL 同批做**，不要第四次单独去动方言文件。

改造期间现役前端行为不变：后端内置一份它的 manifest（那 12 个 token + 现有规则）作兜底，与语言包「内嵌是地板」同构。

## 二、五条铁律 + 一条底色

- **铁律 1｜界面即答案**：能用视图变化回答的绝不用文字。
- **铁律 2｜忽略永远安全**：任何卡片不理都不出事。
- **铁律 3｜一切可见可撤**：账本随手可翻。
- **铁律 4｜撤销即学习**：每域独立胆量系数，撤得多自动变保守。
- **铁律 5｜给犯错的可能**：把错误变便宜，而不是把错误变稀有。凡可逆，一律先做、错了撤、撤了学；预防只站在**不可逆、出系统、批量跨域低置信**的边界上。我们建撤销、账本、胆量系数，不是为了消灭错误，是为了买得起错误。
- **底色｜反羞耻**：不变红、不积债、无 streak、无完成率大字报。计划迁就人。

## 三、已定共识（重编，28 条）

1. **表达入口无处不在**：任何前端必须让"对 agent 说一句话"零成本可达。具体形态（底部框、胶囊、语音键）归端。
2. **响应多态**：做了 → 轻卡 + 撤销；查到 → 浮层 + 视图变化；要确认 → 提案。只有 Companion 是对话流。
3. **上传即 intent**：上传物没有专属规则，就是带附件的输入，走响应多态——查询类只返回回答不落库；单项可逆写入直接做 + 撤销；批量/跨域/低置信写入过提案确认。Library 语境有归档偏置：默认静默入库（纠错成本低，翻目录即改）。
4. **只有 Companion 持久化聊天史**；场外交互走 Exchange 快照（见第十一节），点"在 Companion 继续"才升格。
5. **跨域自动路由**：在哪说都行，agent 全权决定数据落到哪，不设关键词硬规则、不设预分类限制——错了再改（铁律 5）。
6. **Daemon 是产品本体**。时间三层解耦：0 点管语义、石化管画布、节律管时刻表（见第五节）。
7. **Auto-plan 每天自动跑**；Baseline 以 origin=auto 直接生效——"默认正确"意味着默认存在。
8. **无欢迎页无强制导入**：空状态即引导；集成邀请只在情境达成后出现。
9. **心情打卡是轻量组件级功能**，不占一级导航；agent 可从对话直接代打卡（见第十二节类 5）。
10. **Canvas 插件自动直推** + 服务端 Diff（只 insert/update/delete 变化项，防重复与 op-log 噪音）。
11. **三线语义**：实线 = 我放的（origin=manual），虚线 = AI 放的（origin=auto），虚影 = AI 想放的（提案 pending）。这是数据语义；渲染方式归端。
12. **提案是统一资源**：虚影、确认卡、决策卡、集成端的审批请求，底层同一个 proposal 对象（见第六节）。待发池就是提案的服务端队列。
13. **卡片必须堆叠**；堆叠只装 L2 且 ≤3 张；L1 在视图里，L0 在安静小数字里。
14. **每张卡有 DDL**；TTL 方向不对称：先斩后奏的，沉默即接受；先奏后斩的，沉默即拒绝。
15. **背压限投递、不限生成**：Daemon 敞开想，产出全入待发池；池内过期就地作废（用户永远看不到失效提议）；投递时刻重排序 + 合并；补位不即时；急事推、闲事拉。
16. **不做意图显影**（输入时的分类预览）：注意力税 + 两颗脑子问题，详见第七节。信任只靠两层：事中卡片可撤，事后账本可翻。
17. **晨卡是「今日导语」不是契约**：上滑即走、不设 ✓、过午消散——不反对就是接受。
18. **石化是滚动视界**：石化线 = min(当前时间 − 5h, 今天 00:00)，读时派生，无表（见第五节）。
19. **不做月视图**：远期一览的语义是 Deadline 雷达（列表），各端同守。
20. **冷启动节流的是主动性，不是能力**：响应式智能 Day 1 全功率，Daemon 自发 L2 按证据爬坡（见第八节）。
21. **许愿池**：agent 全局可读可写的即兴意图池（见第十节）。
22. **AI 主动发现**：不等"请记住"才行动；分类是判断参考不是硬路由规则（与共识 5 同构）；宁可多记不可漏，错了会撤、撤了就学（见第十二节）。
23. **账本 append-only**：撤销是反向补偿，后悔是新的一笔，不是橡皮擦。
24. **推送预算 ≤3 条/天**；紧迫度增长才能爬梯，同类被忽略两次自动降级。
25. **跨天块两天都计入**：数据一条，足迹两天渲染、两天算数。
26. **足迹**（原"节奏"）：账本 + 河流 + 周信 + 节律可查可钉（见第九节）。
27. **工具全走 operation_log**：包括新增的四个写工具——撤销体系依赖它，无一例外。
28. **关怀不随机制陪葬**：Protector 的熬夜关怀基于连续活跃时长（≈20h）触发，与任何日界线机制无关，永久保留。

## 四、注意力阶梯

| 级 | 名字 | 什么进来 | 语义 | 占比（健康日） |
|---|---|---|---|---|
| **L0** | 静默做掉 | 例行、可逆、意料之内 | 只记账本 + 安静小数字（禁红） | ~80% |
| **L1** | 视图内显影 | 绑定具体时段的机会 | 占位提案，点了才展开；死线 = 它指向的时段本身 | ~15% |
| **L2** | 卡片 | 需注意但不绑时段，或危机 | 进堆叠 | 1–3 张/天 |
| **L3** | 推送 | 出 App 找人 | 预算 ≤3 条/天 | ≤3 |

健康日形态：十几件静默、两三处显影、一两张卡、至多三推送。堆叠是单一停车场，合并同类项强制。

## 五、时间三层：0 点 / 石化 / 节律

三层各管各的，互不干扰：

**1. 0 点 = 语义边界。** DDL 计算、"今天/昨天"归属、日切，全部按用户本地时区的 00:00——与用户心理预期（作业按 0 点算）同频。

**2. 石化 = 滚动视界，而它的体验语义是「翻篇」。**（语义写入 2026-08-07，裁决 #4）

机制与体验是两句话，两句都要说，因为只说机制会让人把它实现成一把锁：

| | 谁负责 |
|---|---|
| **数据正确性** | 石化线 —— `min(now − 5h, today 00:00)`，读时派生 |
| **用户感知** | **0 点换装** —— 昨天安静地变成记录 |

**0 点是仪式时刻，不是锁定时刻。** 这条决定了四个前端怎么画：0 点那一刻不该有任何东西被夺走或变灰，只是昨天换了身衣服。真正的写保护由石化线在五小时后悄悄合上，那时没人在看。

翻篇在三处已经有它的翻译，写下来是为了它们被当成同一件事而不是三个巧合：

- **河流「随滚动石化连续入河」** = 翻篇的**视觉**翻译。不是日切一次性入河 —— 那会让 0 点变成一个事件。
- **「它该去哪儿？」** = 翻篇的**交互**翻译。昨天没做完的事今天**不以欠债形式出现**（反羞耻底色），而是以一个问句出现。
- **对账 = 翻篇的最后一笔，不是任务。** 晚上随手一笔把昨天合上；与晨卡「不设 ✓、过午消散」是同一只手的克制。

⚠️ **跨天未完成块的自动顺延走 L0 静默 + 账本可撤，不走提案** —— 问一句就是一笔注意力税，而这件事的答案在绝大多数情况下是显然的。

块石化条件：块结束时刻 < 石化线。

- 白天任何时刻：今天的块全部活着——下午绝不石化早上。
- 00:00–05:00：昨晚最后 5 小时仍活着（夜猫子缓冲），凌晨 1 点补昨晚的作业照常可拖可改。
- 05:00 起：昨天整天石化完毕。
- 5h 做成参数。判定是读时纯函数，**不建任何表**。
- 石化块从"计划"换装成"记录"，只接受对账动作（完成 / 没做 / 其实做了）与注释；"拖回未来"语义转译为重新安排（原地留痕 + 未来新块），历史不改写。抹除记录是显式稀有动作。
- 对账态 = 已过去但未石化的窗口，全功能可编辑。

**3. 节律 = 运行时刻表。** Daemon 学习用户的惯常入睡/起床时刻（只算真实交互：intent、UI 操作、前台心跳；插件直推、通道消息不算"醒着"）：auto-plan 跑在学到的入睡后静默窗；导语在惯常起床时刻备好、推送；晚复盘在惯常入睡前窗口。冷启动无数据回退 04:00 / 07:30 / 21:00。学到的节律在足迹页可查、可手动钉住（"我就是夜猫子，别管我"）。工作日/周末是否分开学 → 口子。

**关怀**：连续活跃 ≈20 小时触发 Protector——"你快 20 小时没合眼了，上午的安排我先帮你顺延，去睡一会？"值得花一条推送预算，语气是担心不是训斥。顺延本身走提案。

## 六、提案机制（统一资源）

AI 的一切"想做但还没做"收敛为一个 proposal 对象：

- **内容**：拟执行的操作集 + 证据/理由文本 + 呈现提示（含时段则可投虚影）+ TTL（按共识 14 的不对称规则）+ 状态（pending / accepted / rejected / expired）。
- **来源**：agent 对话中的 `propose_decision`、Daemon 的自发产出（经待发池投递）、批量/跨域/低置信的上传识别。
- **端渲染自由**：时间轴型前端投虚影 + 确认卡；卡片型前端只出卡；集成端发审批消息；通道端发一条可回复的文本。同一对象，不同投影。
- **动作恒定**：接受 / 拒绝 / 追问（追问走 Exchange 升格）。过期即作废，落账本可捞回。
- 复合提案在一张卡内分行列出，每行单独接受/拒绝。

字段定稿 → 口子。

## 七、为什么没有显影（防复活记录）

1. 不够实时就别干：闪烁滞后的猜测器让产品显得卡。
2. 注意力税：对 100% 的输入征收余光税，违背铁律 5。
3. 两颗脑子（最致命）：预览器用关键词猜、真路由由 agent 判——一个不预览真实决策者的预览器，比没有更糟。

## 八、Daemon 冷启动：信任爬坡

- **节流的是主动性，不是能力**：Day 1 响应式智能全功率（路由、拆解、排程、归档），爬坡的只是 Daemon 自发 L2 的权限。
- **证据门控，不是天数门控**：每域独立证据量（如连续 3 次一致观察）解锁该域首张自发 L2；阈值是否分域 → 口子。Day 1 接 Canvas 的用户，学业域当天就有正当性——那是导入的事实，不是猜的偏好。**首刀原则**：每域第一张自发 L2 必须是全库置信度最高的那张，宁可晚、不可错。
- **解释可见度与胆量系数反相关**：学徒期卡面显式亮证据（"看你前三天都在 8 点跑步，今天也排上？"）；管家期理由沉入卡内（追问"为什么"永远能召回）；某域撤销连击、胆量下跌，自动回到讲理由。
- 常识 L1 不受门控（基于人类常识而非个人数据）。导语卡诚实降级：没数据就说"今天还是空的，跟我说说今天有什么"。

## 九、足迹（河流与账本合体）

- **近景 = 账本**：每行一句人话 + 撤销 + 跳转，日频动作保日活。
- **远景 = 河流**：操作流、心情融成色带；**随滚动石化连续入河**，不是日切一次性入河。
- **跨天块两天都计入**：凌晨 1 点补完的活，昨天和今天的河里都有它。
- 周日一封周信，散文不是饼图（素材管道 → 口子）。学到的作息节律在此可查、可钉。

## 十、许愿池

- **定义**：未定时间的意图的全局落点，agent 全局可读可写。"想学 Rust""改天去看展""哦对要买牛奶"——投池，**不建 Block**（用户没给时间）。
- **进**：`wish_add` 顺手估 EffortMin（填缝匹配靠它）；写入前查同类，避免同一愿望两次对话记两条。
- **出**：Daemon 填缝——发现空档，按 EffortMin 匹配捞愿望，以 L1 占位提案投出；规划时捎带——排"周末去超市"时把"买牛奶"挂上。
- **治理**（优先级、过期、合并清理）→ 口子。

## 十一、Exchange

非 Companion 语境的交互不留聊天史，但"在 Companion 继续"需要上下文接力：把该次交互的快照（query + 结果 + 涉及对象）存 TempContext，**TTL 10 分钟**；升格时带 temp_context_id，Companion 读作隐式首条上下文。这不是聊天史——快照过期即弃，只有升格那一刻被消费。注入格式 → 口子。

## 十二、AI 主动发现与记录

> agent 不等指令。在自然对话中主动捕捉可结构化的信息，全权判断类别、调用工具落库。以下分类是**判断参考，不是关键词硬规则**（共识 5）。

### 12.1 对话内捕捉（六类）

| # | 类别 | 捕捉什么 | 落点 | 工具 | 要点 |
|---|------|---------|------|------|------|
| 1 | 时间约束 | "下周三交离散""考试提前到周五" | Assignment | `assignment_upsert` | 时间 + 事项绑定 → 建作业；提到已有作业变动 → 改 due（直做 + 轻卡可撤；低置信走提案） |
| 2 | 未定时意图 | "想学 Rust""改天去看展""哦对买牛奶" | Wish；需上下文才懂的开环 → Memory(open_loop) | `wish_add` / `memory_add` | "想/改天/有机会" → 投池 + 估 EffortMin + 查重；不建 Block。"我不想 xxx"是偏好不是愿望 |
| 3 | 自我规律/偏好 | "上午效率高""11 点后不干活" | Memory(preference) | `memory_add` | 关于用户自己的 → 记忆；关于外部世界的 → 资料（类 4） |
| 4 | 外部知识 | "考试重点在第三章""图书馆三楼安静" | Material | `material_add` | 长期参考价值 → 资料库；正文可长，不受 50 字限 |
| 5 | 情绪 | "累死了""压力好大""心情不错" | MoodCheckin（+Memory） | `mood_record`（+`memory_add`） | **直接打卡**：映射 12 种心情最接近的一种，原话入 note；只提取到部分就记大类不猜细节；情绪 + 原因（"考试焦虑"）→ 加记 Memory |
| 6 | 课程元信息 | "老师每周三小测""实验课在 B 楼 201" | Course/Assignment 更新，或 Material(academic) | `assignment_upsert` / `material_add` | 一次性事实 → 资料；周期规律 → 提议 Rule（提案） |

**情绪打卡三边界**：agent 记的标 `source: agent`，可见可改可撤；用户当天已手动打卡则不覆盖，最多补 note；agent 语境不触发 aiResponse（回应就在当下的对话/轻卡里），避免双重回应。

### 12.6 心情有趋势与时效，凡用到心情的地方都按这个读（2026-07-26 追加）

**一次打卡不是心情，一段走向才是。** 「今天焦虑」和「连着四天越来越焦虑」是两件事，后者才该改变系统的行为；而三周前的一次低落，今天不该再有权重。所以**任何要用心情做判断的地方，读的都不是最近一条 MoodCheckin，而是一个派生的心情窗口**：

- **趋势** — 近段时间是在变好、变坏还是平的。改变的是语气档位与主动性，不是内容。
- **时效（权重）** — 越近的打卡权重越高，久远的自然衰减到零。不设硬性截断（「只看 7 天」会让第 8 天的持续低落凭空消失）。
- **时效（新鲜度）** — **距上次打卡多久了，本身就是要告诉 agent 的信息**。这是两回事：衰减决定「旧数据算几分」，新鲜度决定「还能不能开口谈心情」。三周没打卡时，agent 不该拿三周前的低落当今天的底色去扮演 —— 它该知道自己不知道。窗口因此要给出 `staleness` 与一个明确的「无有效心情」态，提示词分支据此闭嘴，而不是硬编一句「用户最近心情低落」。
- **来源** — `source=agent` 的代打卡与用户手动打卡都算，但代打卡是推断，权重低于用户自己按下的那一次。

这与石化、默契同属**读时派生**：不建趋势表、不跑定时任务，从 `MoodCheckin` 序列现算，参数错了下次读就自愈。

**用得到的地方（都走同一个窗口，不要各算各的）**：companion 的上下文注入 · 默契（rapport）的语气档位与主动性门槛 · Protector 的 20h 关怀措辞 · 晨卡导语与晚复盘 · 提案卡的语气 · auto-plan 的强度（连日低落时不该排满）。

**一条边界**：心情窗口是**语气与节奏**的输入，不是**内容与拒绝**的输入。锁定块的 409 拒绝不查心情 —— 拒绝要即时、确定、可测；一个拖不动的块，用户需要立刻知道为什么，而不是等系统先想想他今天心情如何。心情自适应属于展示层的可选增强，且要克制。

### 12.2 Daemon 扫描（两类，属第八节机制，不进对话提示词）

- **习惯模式**：定期扫账本，N 次一致观察 → Rule 提案（首刀原则约束）。
- **排程冲突**：排程时检测时段重叠、DDL 挤兑 → 决策提案，不静默解决。

### 12.3 记录纪律

- 单条 ≤50 字（Material 正文除外），只记关键事实 + 触发来源，不记对话全文。
- 写入前查同类去重（实现方式 → 口子）。
- 全部走 operation_log，计入 L0 小数字与账本——**先看得见，才撤得了**。
- 不确定 → 记。错了用户会撤，撤了就学（铁律 5）。

### 12.4 不记录（防污染）

闲聊寒暄；对 agent 本身的评价（走 feedback 管道）；一次性查询的中间结果；纯情绪无原因（"烦死了"→ 打卡即可不建 Memory；"烦死了，明天考试"→ 打卡 + Memory）。

### 12.5 提示词注入（companion_agent.tmpl）

```
## 主动发现与记录
不等用户说"请记住"。对话中主动捕捉以下信号并调用工具：
1. 时间+事项 → 建/改作业
2. "想/改天/有机会" → 愿望池（顺手估耗时，写前查重）
3. 关于用户自己的规律/偏好 → 记忆
4. 有长期参考价值的外部知识 → 资料
5. 情绪表达 → 直接心情打卡（映射最接近的心情，原话入 note）
6. 课程的老师/教室/规律 → 更新课程信息；周期性的提议规则
纪律：单条 ≤50 字（资料正文除外），只记事实与触发来源；
偏好是关于用户自己的，知识是关于外部世界的——分清楚；
不确定就记——错了会被撤，撤了你就学（铁律5）。
```

## 十三、三个落地答案（体验逻辑 → 数据形状）

1. **胆量系数**：不是新事实，是账本的读数。按域建缓存行（session_id × domain × score × evidence_count），OperationLog 是唯一真源，缓存可随时重放重建。
2. **石化**：纯读时函数 `block_end < min(now − 5h, today_00:00)`，**无表、无批量改写、无竞态**；参数错了改参数即自愈——数据层的容错。节律观察数据（入睡/起床时刻）单独存，只服务时刻表学习，不承载石化。
3. **过去事件的撤销**：反向补偿，账本只增不改（revert_of: op_id + before 快照）。河流里既看得到行动、也看得到后悔——与反羞耻同构。
