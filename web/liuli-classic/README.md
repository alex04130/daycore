# 琉璃初版 · 页面制

**最老实的那一版。** 底部或侧边一条导航栏、五个页面（今日 / 资料 / 陪伴 / 心情 /
设置）、一列一列的卡片。没有画布，也没有手势 —— 所有能力都摆在明面上。

它是四端里的**对照组**：留着它，是为了看清另外三个「非常规」到底非常规在哪。

## 跑起来

```bash
npm install && npm run dev      # http://localhost:5178
npm run build                   # tsc + vitest + vite build
```

## 四个「现在」，和一个第二维度

| | 「现在」是什么 |
|---|---|
| 汀 | **那一件** —— 屏幕上唯一该显示的东西 |
| 纸屿 | **一个位置** —— 流里画线的地方 |
| 长卷 | **一个坐标** —— y、高度、层级 |
| 初版 | —— |

初版**没有**第四种回答。它给的是**第二个轴**：一天不再是唯一的一天。

前三端的 `store.ts` 里都写着同一行 `const date = api.todayIso()`，而且从不问别的
日子。周条、月历、跳转日期、回到今天、规划区间 —— 这些都是同一个概念换了件衣服，
而另外三端**没有任何地方放得下它**。所以范式专属的纯逻辑模块是
[`src/days.ts`](src/days.ts)，不是又一个「什么是现在」。

## ⚠️ 日期算术的两个经典 bug，和被钉住的测试时区

这是四端里唯一做日期**算术**的。它有两个各自只在特定时区才看得见的 bug：

| bug | 只在哪种时区暴露 |
|---|---|
| `new Date('2026-08-11')` 按 UTC 解析 | 格林尼治**以西** |
| 整日差用 `Math.floor` | **有夏令时**的时区 |

所以 `vite.config.ts` 把测试时区**钉死在 `America/Chicago`** —— 它两样都占。在 UTC
（容器的默认值）下，这两种破坏都不会让测试变红，断言就成了摆设而报告依然是绿的。

代价说清楚：一个进程只有一个时区，所以这些测试**永远不会**在读者自己的时区下跑。
这是对的取舍 —— 这个模块的职责是在**任何**时区都正确，而只跑机器碰巧设成什么的
测试，测的是那台机器。

## ⚠️ 原型里最大的一块逻辑，这里整块扔掉了

原型的桥接层用「扫未来 28 天的块、按标题聚合、出现 ≥2 次就算一条规则」**归纳**出
规则，还配了一条硬规矩：归纳出来的规则一律不可写（因为把猜出来的周期展开回去，两次
巧合会变成七节课）。

那是给**没有规则实体的 mock core** 打的补丁。真后端有 `ScheduleRule`，带重复、
时区、墓碑，而且展开已经并进了 `GET /api/plan` 与 `/api/plan/range`。照抄归纳
不只是重造一个不存在的问题的解法 —— **两边都会展开，每条规则出现两次。**

留下来的是 [`src/rules.ts`](src/rules.ts)：把一条规则**说成人话**。它返回的是
catalogue 的 key 而不是句子（同 纸屿 的 `hourLabel`），并且它描述的是
`internal/schedule/expand.go` **真正会做的事**：

- `interval < 1` 服务端会夹成 1，所以 0 不是「每 0 天」而是「每天」。
- `weekly` 的 `by_weekday` 为空时回落成**起始日那天的星期**，不是「每天」。
- `monthly` 的 29–31 号，**没有那一天的月份直接跳过**，不顺延到月末 —— 这是另一个
  承诺，所以它有自己的一句话。
- 缺锚点的 `every_n_days` / `monthly` / 带间隔的 `weekly` **永远不会生效**。后端
  只是返回 false，什么也不说，所以这一行是读者唯一能知道这件事的地方。

## ⚠️ 角标是这个范式的税

另外三端只有一个面，所以「有事等你」由那个面自己回答。有了第二个页面之后，站在其中
一页的人看不见另外四页，唯一诚实的说法就是在标签上做个记号。

所以角标只从**已经加载的状态**推导，而且今天只有「今日」有数字。「陪伴」需要的是
「你上次看之后来了几条」，没有任何地方存这个；拿 `updatedAt` 编一个出来，对的次数
和错的次数差不多。**没有角标的标签说「没什么可报的」，猜出来的角标是在一个人们会
信的位置上说假话。**

## 明确不做的（不是漏了）

| | 为什么 |
|---|---|
| **负面情绪自动邀请练习** | `MoodKind.Valence` 是 `json:"-"`，后端注释写明「never shown to the user」；`/api/ai/mood` 只回 `{response}`；`exerciseOffered` 是客户端写什么存什么。前端自己判断哪些心情是坏的 = 在客户端复刻一个产品**有意拒绝渲染**的判断。改成：三个练习常驻，谁想做谁做，`exerciseOffered` 记录他真的选了哪个。 |
| **「仅管理员可见」的控制台入口** | `GET /api/me` 有 `isOwner`，但**没有角色**。所以条件渲染对 owner 是对的、对每一个靠角色拿到权限的管理员都是错的 —— 把门藏起来，正好藏的是拿到钥匙的那些人。改成无条件显示 + 一句说明谁能进。 |
| **线程副标题「{n} 条消息」** | `ChatThread` 没有 `messageCount`，要拿就得为每个线程各拉一次消息列表。 |
| **前端自己的 7 天规划上限** | 真上限是 `AUTO_PLAN_MAX_DAYS`，运行时配置，**不下发给客户端**。任何写死的数字在配置成 14 的部署上都是错的，而且原型是**静默截断**——用户点了第 10 天却只有 7 天亮起来。改成照发，然后显示后端那句已经带着这个部署自己数字的 `range_too_large`。 |
| **Canvas / ICS / 课表截图导入** | 端点都是真的，但它要文件选择器 + 多步候选确认，而那个候选面板要被三种导入复用。值得单独一批做对，不值得先做半个。资料页的规则那一栏直接把这句话写在屏幕上。 |
| **引导流程的账号级持久** | 全库 grep `onboard` 在 Go 侧零命中，Session 只有 `interactionCount` / `signInPrompted`。所以引导只能是设备本地状态，换设备会重放。要改是后端加一个 preferences 键，属于另一批。 |
| **前端伪流式打字 / 前端决策倒计时 / 前端 crash sweep** | 三件事后端都已经做了（`FailPendingMessages()`、服务端计时）。前端再做一份就是第二个真源。 |

## family 是 `liuli-classic`，不是并进 `default`

初版渲染的 token 名和现役 `web/frontend` 一模一样（就是后端的 `themeVarWhitelist`），
所以并进 family `default` 能让老前端里做过的主题在切换之后继续可用。

它还是自己一个 family，因为 **`default` 不是一个设计系统** —— 它是「没报 build 的
请求按哪套判」，是匿名与未知客户端的桶。故意搬进去的 build 会和忘了自我介绍的
build 分不出来，那个 family 就不再意味着任何东西了。

主题延续有一条不花这个代价的路：`PUT /api/admin/frontends/builds/{hash}/family`，
由**运维**在切换的那一刻决定。两层身份（构建指纹 + 声明的 family + 运维可覆盖）
就是为这件事建的。

## 它提议零个 kind

汀 要 `shadow`、纸屿 要 `easing` + `radius`、长卷 要 `ratio-or-length`。初版一个
都不要 —— 它开放给主题的每个值都是颜色、长度或时长，都在内嵌的六种里。

「为了对称」提议一个，是平白往运维桌上放一个决定，而第三档只在这种事很少发生时才
便宜。所以「不需要」这件事本身有一条断言钉着：
`internal/theme/frontend_manifest_test.go` 的 `TestLiuliClassicProposesNoKinds`。

## 多语言闸门比另外三端多了三条规则

前三端的每个 key 都是 `t('literal')`，初版两样都不是：

- 有**页面列表**，所以导航是 `t(\`nav.${id}\`)`；
- 有 `src/rules.ts`，它把 catalogue 的 key 当**数据**返回，所以 `rules.weekly`
  在整个代码库里都不会出现在 `t(...)` 里。

老闸门会把这些全报成孤儿，而**朝「删掉这条翻译」的方向出错的检查，比没有检查更糟**。
所以提取多了三条，每条都是机械的、都不需要谁去维护一张名单：模板字面量的前缀、
`key:` 位置上的点式字面量、以及把域写在源码里的四个家族逐条核实。

唯一还查不到的是 `theme.${id}` —— 那份内置主题列表的真源在 Go 里。那一条由
`TestEveryBuiltinThemeHasAName` 在后端补上：后端加第五个内置主题而前端没给名字，
它会红。
